# SoloVerse 改善記録（2026-09-15）

## Step 1 — 実行ログ・タイムラインの問題の洗い出し

| 問題 | 根拠・原因 | 判定 |
| --- | --- | --- |
| GPT-OSSで空応答のフォールバックが繰り返される | 80〜120トークンの短文枠を推論込みの上限へそのまま渡し、空文字を思考漏れと同じログにしていた | 空応答はログで確認。推論による枠の消費は有力な原因だが、当時のfinish_reasonがないため断定不可 |
| 初期投稿が二重に生成される | 同一ユーザーのSeedログが2回。件数チェックと非同期LLM呼び出しの間に別リクエストが入る | 同時呼び出しで再現可能 |
| 質問より前に回答、親より前に返信が表示される | 自律投稿を生成後ランダムに最大19分過去へ保存 | コードで確定 |
| 別の投稿への返信になる | 返信先を投稿IDではなくhandleの最新投稿から後で解決 | コードで確定 |
| いいね・返信がリロードまで更新されない | 差分APIが新しい親投稿だけを返し、画面側も既存投稿を更新しない | コードで確定 |
| 同じ秒の投稿・自分の投稿直前のAI投稿を取り逃す | sinceが秒精度の厳密な大なり比較。自分の投稿で取得カーソルを先へ動かす | コードで確定 |
| 直後に住人が増える／上限超過 | 成長時刻未設定なら直ちに生成。19人から2人追加できる | コードで確定 |
| 似た比喩・独り言が多く、質問への答えが薄い | 過度に短い本文指定、テーマ強制、observerの相槌限定、ventの愚痴誘導が重なる | 提示された文章とプロンプトから判断。実モデルの品質には変動がある |
| 読み込み失敗が「投稿なし」に見える | Seedのエラーを画面が握りつぶす | コードで確定 |
| 疑問符なしの質問・呼びかけに返信がない | 「誰が好き」「みんな」「無視しないで」を質問判定が認識せず、smallでは返信が30%の抽選だけになる | 新規アカウントのDBで返信予約0件を確認 |
| 作品ファンが作中人物のような名前・経歴になる | 抽象的なロールプレイ禁止だけではモデルが `JediJin`、`Kira Skywalker` 等を生成した | 新規アカウントのDBで確認 |

## Step 2 — 不具合修正

- Groq GPT-OSSの推論強度をlowにし、推論用トークンの余裕を追加。Qwenの対応モデルは推論なしに設定。
- 空応答／途中切れ／JSON不正／思考混入を区別し、終了状態・消費トークン数のみログへ記録。本文はログへ出さない。
- 不正出力は5分休止し、同じモデルの連続失敗を抑止。待ち行列内でもタイムアウトし、期限切れリクエストを送信しない。
- ユーザーごとに初期生成とバックグラウンド処理を直列化。初期投稿を検証後まとめて保存。
- 自律返信先を既存投稿ID、または同じ生成結果の先行要素indexで指定。存在しない返信先・未来のindexは保存しない。
- 自律投稿・返信を生成時刻で保存し、最大6件と重複本文の除外を適用。
- 初回成長は6時間待機。追加人数は20人までに制限。
- 既存投稿の再取得、同じ秒の再取得とID重複排除、過去投稿のカーソル取得を追加。
- 画面の初期化エラーと再試行ボタン、返信数・いいね数のラベルを追加。
- 日本語の疑問語と「みんな」「無視しないで」等の呼びかけを検出。smallでも1〜3分以内に最低1件の返信を予約。
- 旧判定で取りこぼした直近24時間の投稿を定期キューが自動救済。投稿直後の処理との重複を避けるため2分経過後を対象にする。

## Step 3 — 修正後に選んだ追加改善

1. 無料枠を節約し、生成されたトレンド投稿で世界が埋まらないようにする。
2. 「誰が何を好むか」を保ち、質問に内容のある回答が返るようにする。
3. 住人の個性を画面で確認でき、スレッド内の会話を続けられるようにする。

## Step 4 — 追加改善の実装

- トレンドを直近7日・最大500投稿のハッシュタグ集計へ変更。同じ投稿内の同じタグは1回と数え、世界ごとに上位3件を保存。LLM呼び出しは0回。背景ジョブで約5分ごとに更新。
- 自律生成間隔を環境変数で変更可能にした。60分などへ伸ばして無料枠を節約できる。
- 新規キャラクターへ具体的な好み・得意分野・日常を持たせ、生成バッチ間の名前重複を抑止する指示を追加。
- ロールプレイが明示されない場合は作品を楽しむファンとして会話する指示を追加。既存の表示名は変更しない。
- ventは「愚痴を許容」と明確化し、全員の発言を否定的にしない。observerでも質問には具体的に答える。
- 返信生成時にその住人の最近3件の発言を追加。全文検索や長期記憶ではなく、短い履歴による継続性の改善。
- 質問には少なくとも1件の返信を予約。スケジュール後にLLMが失敗した場合など、返信成功そのものの保証ではない。
- 「AI住人」タブへ性格・興味・話し方を表示。スレッド内で返信先を選択可能にし、30秒ごとに更新。
- 作品テーマの住人名・経歴・初期投稿に悪い例と良い例を明示し、現実のファンとして生成する指示を強化。
- 「AI住人とAI投稿を作り直す」を追加。アカウントとユーザー投稿を残し、AI住人・AI投稿・AI通知だけを現在の生成ルールで置き換える。

## 検証と適用範囲

- 模擬API・一時DBでバックエンドの回帰テストを実行。実際のAPIキーや利用枠は消費しない。
- フロントエンドの本番ビルド・TypeScript検査を実行。
- 起動だけでは既存のAI住人・AI投稿を勝手に書き換えない。不自然な既存世界は画面の再生成操作で、アカウントとユーザー投稿を残して明示的に置き換えられる。
- 実モデルでの文章品質と各アカウントの利用可能枠は、再起動後の投稿で確認が必要。
- 直列化は1プロセス運用向け。複数サーバー間の排他制御は今回の対象外。

## 再開方法

設定済みのAPIキーはそのままで、バックエンドとフロントエンドを再起動する。DB削除は不要。

```bash
npm --prefix backend start
# 別のターミナル
npm --prefix frontend run dev
```

任意の節約設定は `backend/.env` に追加する（同名項目があれば編集）。

```dotenv
AUTONOMOUS_INTERVAL_MINUTES=60
WORLD_TIME_ZONE=Asia/Tokyo
LLM_INVALID_OUTPUT_COOLDOWN_MS=300000
AI_DIRECT_REPLY_MAX_DELAY_MINUTES=3
```

モデル仕様の参照: [Groq reasoning](https://console.groq.com/docs/reasoning)、[Groq API](https://console.groq.com/docs/api-reference)。
