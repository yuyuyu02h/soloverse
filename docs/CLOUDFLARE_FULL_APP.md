# Cloudflare完全版（個人利用・無料枠前提）

- 画面: https://soloverse.pages.dev
- API: https://soloverse-api.my-ec-site.workers.dev
- DB: D1 `soloverse-private`（バインド名 `DB`）
- 今回は管理者アカウント1件のみを登録。ローカルの世界設定・投稿・住人は移行しません。
- 管理者のメール・パスワード: Git対象外 `.private/ADMIN_CREDENTIALS.md`。ローカルと同じものです。

## 構成

Pagesは静的な画面、Workersは既存ExpressのAPI、D1は永続データを担当します。DB接続はリクエストごとに分離し、ローカル実行では従来のSQLiteを使います。D1のスキーマは `cloudflare/migrations` にあります。新規登録はサーバー側で停止し、認証済みの管理者ID以外も拒否します。

Cloudflare版のパスワードは、ブラウザー側PBKDF2-SHA256（60万回、アプリ識別子と正規化メールをsaltに使用）とサーバー側PBKDF2-SHA256（10万回、アカウントごとの暗号乱数salt）を組み合わせます。最初の前処理結果はパスワードと同様に重要なので、HTTPSだけで送信し、ブラウザーへ保存・ログ出力しません。DBには最後の照合値だけを保存します。APIは方式の識別子を必須とし、回数の引き下げや旧bcryptへの切り替えをCloudflare側では認めません。通常のローカル版は既存のbcryptを継続します。

Workers本番はPBKDF2を一度に10万回までしか処理できず、60万回はローカルで通っても本番では失敗しました。この制約に合わせて前処理を分担しています。DB照合値を盗まれた場合のパスワード推測には、両方の処理が必要です。

### 登録・ログインの回数制限を本番で維持する

- **本番（`SOLOVERSE_RUNTIME=cloudflare`）は、同一IPから15分に10回まで。解除しない。** 登録・通常ログイン・管理者ログインで共通のD1カウンターを使う。登録停止中の登録要求は拒否し、カウンターを増やさない。
- ローカルの発表環境では、来場者ごとの切り替えを妨げないよう、この制限を適用しない。
- 環境の区別はサーバー設定で行う。ブラウザーのパラメーターで本番制限を解除できるようにはしない。
- 公開前に `auth-production-limits.test.js` と `auth-repeat.test.js` を確認する。前者で本番の11回目が429になること、後者でローカルの連続操作が通ることを検証する。

2026年10月18日の追加機能は、@指定の返信優先・自分の投稿削除・スレッド内の区切り線調整です。Workersの更新前にD1へ `0003_post_deletion_mentions.sql` を適用します。ローカルDBは起動時に必要な列を追加します。Pagesのプロジェクト名は `soloverse`、Workerの接続許可は新URLと移行元URLを含め、`APP_URL` は新URLにします。

## APIキー（ユーザーが設定）

Cloudflareダッシュボード → Workers & Pages → `soloverse-api` → Settings → Variables and Secrets → Add。

- Type: **Secret**
- Name: **GROQ_API_KEY** / **GEMINI_API_KEY** / **OPENROUTER_API_KEY**（それぞれ別のSecret）
- Value: 各社で発行した自分のAPIキー
- 保存・Deployまで実行

キーをチャット・GitHub・Pagesの環境変数・NEXT_PUBLIC_変数に貼らないでください。接続順はGroq → Gemini → OpenRouterです。各社のキーを登録した接続先だけが対象になります。月額0円を保つにはGroq・GeminiのAPIプロジェクトで無料枠を使用し、OpenRouterは `openrouter/free` に固定します。アプリの回数制限は、有料プランの契約そのものを無料に変更する機能ではありません。

JWT_SECRETとADMIN_USER_IDSはサーバー用Secretsです。初期値は `.private/cloudflare-server-secrets.json` へローカル保存し、Cloudflareへ登録します。AIキーはこのファイルに含めません。秘密値の登録後も `wrangler deploy` は既存Secretsを保持します。

## 無料枠を使う動作

- AI依頼はUTC日付ごとに全体で100回・10万トークンを上限として予約します。バックグラウンド分は返信用40%を残します。
- これはアプリ側の上限です。提供元の分単位の制限・利用枠も優先します。上限時は生成を待たせ、日本時間9時のアプリ枠更新後に再開できます。
- 画面からの利用確認が約5分途絶えると、自動生成を停止します。閲覧中もまとめて作った候補を時間差で公開します。
- Cronは1分単位。返信を優先し、その他の作業を別々の回へ分散します。D1上の期限付きロックで二重実行を防ぎます。
- 投稿候補・住人・観客コメントは、JSONを使ってまとめて保存し、D1の1クエリ100パラメーター制限を回避します。1回の公開は最大4候補です。
- 無料枠を超えたとき自動アップグレードする処理はありません。Cloudflare・AIの契約を有料へ変更する操作も行いません。

## 開発・更新

```sh
npm ci
npm ci --prefix backend
npm ci --prefix frontend
npm test --prefix backend
npm run build:cloudflare
npm run deploy:worker
```

PagesのGitHubビルドコマンドは `npm ci --prefix frontend && npm run build:cloudflare`、出力は `frontend/out`、本番ブランチは `codex/celebrity-experience` です。Workersは `npm run deploy:worker` で更新します（現段階ではPagesのPushだけではAPIコードは更新されません）。Workerのビルドにはbackendの依存関係も必要です。

画面だけへ戻す場合は `npm run build:cloudflare:preview`。APIの公開URLを変える場合は、ビルド時の `CLOUDFLARE_API_URL` とWorkerのCORS_ORIGIN/APP_URLを併せて設定します。

DBの構造変更は新しいマイグレーションを追加して `npm run migrate:cloudflare` で適用します。`scripts/generate-d1-schema.cjs` は初期スキーマの生成用で、空の一時DBだけを読みます。既存DBへ初期マイグレーションを再適用しません。

Cloudflareローカル検証には `cloudflare/.dev.vars.example` を `.dev.vars` にコピーして架空アカウントを使用します。`.dev.vars` はGit対象外です。本番のAPIキーを入れる必要はありません。ローカル検証では `--local` を必ず使用します。

## 検証の範囲

既存テストに加え、D1接続の並列分離・一括保存・認証方式の検証を行います。実際のWorkers上でのログイン、D1永続化、APIキー設定後の実AI生成を別々に確認します。ローカルでのCPU時間測定だけでは本番の無料枠内での稼働保証にはなりません。長時間稼働時の無料枠・D1行読み取り量は運用後も確認が必要です。

## 発表用アカウントのログアウト初期化

現在の管理者1名のみ、体験画面でログアウトを確定すると、全テーマの投稿・AI住人・記憶・世界設定・通知・生成待ちを削除し、次回ログインでオンボーディングへ戻ります。キャンセルやブラウザーを閉じる操作では初期化しません。管理画面のログアウトも初期化しません。認証情報・管理者権限・使用済みAI利用枠は保持します。同じアカウントの他の体験セッションは失効します。処理は世界更新と直列化し、一括処理に失敗した場合はデータとセッションを保持します。

**無効化:** `cloudflare/wrangler.jsonc` の `DEMO_RESET_USER_IDS` を空文字にして `npm run deploy:worker` を実行します。フロントエンドの再公開やDB変更は不要です。追加の管理者は自動で対象になりません。ローカル版では未設定のため既定で無効です。

実装は `backend/src/services/demoReset.js` に分離しています。完全に撤去する際は同ファイルとauthルートの呼び出し、フロントエンドの `resetOnLogout` 分岐・確認画面・logoutの `resetDemo` 分岐、設定項目と専用テストを除去します。

## 初期投稿の利用枠待機

世界・モード変更と初期投稿の生成は別処理です。初期投稿は最大4件・登場する住人は最大4人に抑え、内部プロフィールの照合用fingerprintはAIへ送信しません。Groq等の枠が足りない場合はHTTP 202で待機理由と再試行の目安を返し、世界変更自体の失敗として扱いません。提供元の回復時刻が分かる場合はその時刻、分からない場合は原則1分後、アプリの日次上限は次のUTC日付更新（日本時間9時）を使います。枠不足で検査できなかった候補は未検査のまま保存し、検査を通るまで公開しません。

`0002_seed_wait.sql` は待機理由の列を追加し、旧処理で提供元の枠待ちによって空のまま30分止まっていたプールだけを再試行可能にします。投稿・住人・世界設定は削除しません。

## 世界の更新ロックと初期投稿の分割

Cloudflareの初期投稿は、候補の生成、内容検査、公開をそれぞれ別リクエストで実行します。検査・公開へ進む待機は画面が表示中なら約1.5秒後に自動で続きを取得し、利用枠待ちは指定時刻まで待機します。再生成も住人の更新で一度応答し、画面側の既存の初期投稿処理が続きを進めます。ボタンを押し直す必要はありません。

自動生成では、候補の補充と検査・公開を同じCronに詰め込みません。準備済みの候補は次の毎分処理で優先して検査し、その次の処理で公開します。本人への返信は引き続き候補の準備より優先します。投稿候補数・公開予定時刻・生成ルールは維持します。

D1への通常処理は1実行45回までに制限し、残り5回を更新ロックの解除と計測保存用に残します。書き込みの一括処理は必要な回数を先に確認し、収まらない場合は一部だけ保存せず次回へ回します。3社への切り替え、再生成、Cronの補充・検査・公開、会話履歴のある返信、上限付近の中断後のロック解除を一時DBと模擬AIで検証します。DBの構造変更はありません。

世界を更新中の通常投稿は409で返し、本文を残して再試行を案内します。初期投稿の更新待ちは202です。更新ロックは通常の完了・例外時に解除し、異常終了時の期限は3分です。Worker間でリクエストの寿命をまたぐI/O待機キューを共有しません。ローカルサーバーの既存の直列キューは維持します。

一時的なDB障害でユーザー・セッションの照合に失敗した場合は、認証失敗の401と区別して503（`AUTH_UNAVAILABLE`）を返します。ブラウザーの認証情報と投稿本文は保持し、初回のセッション確認に失敗した画面では再試行できます。署名不正・期限切れ・ログアウト済みのセッションは従来どおり401です。

## Groq → Gemini → OpenRouterの切り替え

公開用の設定は `LLM_PROVIDER_ORDER=groq,gemini,openrouter`、各社1モデルです。Geminiは `gemini-3.5-flash-lite`、OpenRouterは無料専用の `openrouter/free` を使います。Groqが成功した場合は後続へ送りません。提供元の枠不足、429、認証エラー、通信エラー、タイムアウト、空応答・不正JSONの場合は次へ進みます。全体の安全上限（日次100回・10万トークン）や利用者の非アクティブによる停止では会社を切り替えて上限を回避しません。全社が利用できなければ待機します。

1社あたりの待機は最大18秒、全体60秒です。キー・モデル名は運用者が登録したものを使用し、初回公開時は各社の実接続を架空データで確認します。秘密キーをコードやMDへ書き込まず、CloudflareのWorker Secretsへ登録してください。キーの未登録や実モデルの制限により、3社すべてを使えるとは限りません。

モデルと無料枠の確認先（2026-10-17）: [Gemini公式料金表](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)、[OpenRouter Free Models](https://openrouter.ai/collections/free-models)。無料枠・利用可能モデルは各社側で変更されることがあります。

管理者の `POST /api/admin/ai-check` は任意の `provider`（`groq` / `gemini` / `openrouter`）で1社だけを接続確認できます。通常の生成順や世界の設定は変更せず、固定の架空文だけを使います。省略時は通常の切り替え順で確認します。
